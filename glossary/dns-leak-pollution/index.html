百科：DNS污染与SNI阻断原理及解决办法

📚 知识分类：网络代理基础架构 📅 核验更新：2026年3月 ✅ 校验：技术专家审校

很多新手在翻墙过程中会遇到“明明节点连接正常，但部分网页就是解析失败”的情况， 这通常是由于触发了 GFW 的两大核心审查机制：DNS 污染（DNS Cache Poisoning） 与 SNI 阻断（Server Name Indication Block）。

一、什么是 DNS 污染？

互联网通过域名访问网站时，首先需要向 DNS 服务器询问该域名对应的真实服务器 IP。 传统的 DNS 查询基于明文 UDP 53 端口。当你在国内宽带下查询未加密的海外受限域名（如 twitter.com）时， GFW 会在权威服务器应答之前抢先返回一个虚假的、不可达的错误 IP，使你的电脑连向死胡同。这就是典型的 DNS 污染。

二、什么是 SNI 阻断？

在建立 HTTPS 安全加密连接前，客户端发送的第一个 Client Hello 握手数据包中包含了一个名为 SNI（服务器名称指示） 的明文字段，用来告诉服务器你想访问哪个具体域名。 防火墙实时审查这个明文字段，一旦发现命中受限黑名单，便会立即伪造 TCP RST 重置包强行掐断连接。

三、现代客户端如何彻底解决？

  1. Fake-IP 机制：Clash 等客户端在收到本地 DNS 请求时，不经过任何公网查询，而是直接在本地生成一个假IP（如 198.18.0.1）立即返回给浏览器。真实域名被打包加密后发送给境外专线节点，由境外节点在远端完成无污染解析；
  2. DoH / DoT 加密 DNS：使用 DNS over HTTPS 技术，将 DNS 请求装进 TLS 加密通道中，防火墙无法窥视查询内容；
  3. ECH（加密客户端问候）：新一代 TLS 规范将 SNI 字段全面加密，从根本上终结明文审查拦截。
